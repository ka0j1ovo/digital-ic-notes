本章是“从电路到系统”的桥梁：前面几章算的是一个门多快，这一章算的是整颗芯片能在多高的频率下正确工作。所有公式最后都归结为两个不等式——建立时间约束和保持时间约束。

0 导学：为什么时序比逻辑更难

逻辑设计只关心“功能对不对”，时序设计关心“在给定频率下，信号能不能按时到达”。难点在于：

• 延时不确定：同一个门在不同 PVT（工艺、电压、温度）下延迟能差 2~3 倍；

• 路径成千上万：一条路径不满足，整颗芯片就失败；

• 无法靠仿真穷举：输入组合太多，只能靠静态时序分析（STA）数学证明。

PPT 第 3 页给了两条根本思路：

① 同步系统：产生一个全局时钟 CLK，用触发器周期性地“对齐”所有信号，把不确定的延时变成确定的时序关系；

② 异步系统：干脆不要全局时钟，用握手（self-timed）让快的等慢的，局部同步。

现代芯片 99% 是同步系统：因为“对上表”比“互相等待”简单得多、也快得多。 本章绝大部分内容都在讲同步系统的时序。

2 同步电路与关键路径

2.1 同步电路的本质

同步电路 = 同一时钟驱动的触发器 + 触发器之间的组合逻辑（不允许组合反馈）。把触发器“抽象掉”之后，剩下的就是一张有向无环图（DAG）。

为什么不允许组合逻辑反馈？因为反馈会形成环路，输出取决于自己，时序无法用“一条路径的延时”来分析——那属于时序逻辑（第 7 章）的范畴。

2.2 路径延时：tcd 与 tpd

一条组合路径有两个延时（PPT 第 17~19 页）：

• t_pd（传播延时，propagation delay）：输入变化到输出最终稳定的最长时间，走的是最慢的分支；

• t_cd（污染延时，contamination delay）：输入变化到输出开始变化的最短时间，走的是最快的分支。

在“分支-汇聚”结构里（一个输入分成几条路径再汇合），两者差别很大：最快的分支决定 t_cd，最慢的决定 t_pd。建立时间看 t_pd（最慢），保持时间看 t_cd（最快）——这是本章最关键的一句话。

2.3 延时有多少个？

PPT 第 20 页算了一笔账，很能说明 STA 的必要性：假设一个组合逻辑有 7 条路径：

7 条路径 × 上升/下降 2 种 × (tcd, tpd) 2 种 × PVT 角 2 种 = 56 个延时(10-1)

实际芯片里有几百万条路径，再乘上各种角，根本不可能靠仿真穷举。所以工业界用静态时序分析：不仿真，直接对图做数学运算（§7）。

2.4 关键路径

把所有路径的 t_pd 都算出来，最大的那个叫关键路径（critical path），它决定了芯片的最高频率：

Tc > tpd(max) → f < 1/tpd(max)(10-2)

3 建立时间约束：决定最高频率

3.1 把约束写成不等式

考虑从 DFF1 到 DFF2 的一条路径。数据在时钟沿 t=0 从 DFF1 发出，必须在下一个时钟沿（t = Tc）之前到达 DFF2，并且提前 t_su 稳定：

tpcq(DFF1) + tpd + tsu(DFF2) < Tc(10-3)

左边是“数据到达时间 + 需要的建立窗口”，右边是“一个时钟周期”。整理成裕量（slack）的形式：

slacksetup = Tc − [tpcq + tpd + tsu] > 0(10-4)

只要所有路径、所有 PVT 角下 slack 都 > 0，电路就能工作。slack 最小的那条路径，就是建立时间关键路径。

3.2 标称频率与超频

PPT 第 26 页区分了两个概念：

fnom = 1/[tpcq + tpd + tsu]worst （高温低压最坏情况）(10-5)
foc = 1/[tpcq + tpd + tsu]typical （常温常压典型情况）(10-6)

这解释了一个现象：CPU 标称 3 GHz，玩家却能“超频”到 4 GHz——因为标称值是按 worst case（高温、低压）保证的，而典型芯片在常温下确实更快。

4 保持时间约束：决定最短路径

4.1 为什么会有保持时间问题

考虑移位寄存器：DFF1 和 DFF2 用同一个时钟沿。理想情况下，时钟沿一到 A 立刻更新，B 采样到的是 A 的旧值。但如果 A 的新值来得太快（t_cd 很小），它就会“追上”同一个时钟沿，被 DFF2 采到——一个沿穿过了两个触发器，数据错了。

所以数据不能到得太快，必须等 DFF2 把旧值采完：

tccq(DFF1) + tcd > thold(DFF2)(10-7)

注意这里用的是 t_ccq（污染时钟到 Q，最快的那部分）和 t_cd（最快路径），因为保持时间关心的是“最快能多快”。 这与建立时间刚好相反。

4.2 保持时间违例怎么修

保持时间违例不能靠降频解决（因为与时钟周期无关），只能：

• 在路径上插入缓冲器（增加 t_cd）——PPT 第 63 页说得很直接：“可故意插入 buffer 满足保持时间”；

• 用更强的触发器（增大 t_ccq）；

• 调整时钟偏斜（让捕获时钟晚一点到）。

这就是为什么保持时间违例在工程上更“可怕”：它不受频率约束，一旦违反，只能改版图/加延时单元，而且往往出现在“太快”的工艺角（FF、低温）。

流水线的本质是：用“延迟（latency）”换“吞吐率（throughput）”。 它把长路径切成若干短路径，于是时钟频率可以成倍提高，代价是单次运算要多等几个周期、面积和功耗增加。现代 CPU 的十几级流水线就是极端的例子。

流水线深度怎么选

切得越细，频率越高；但每插一级寄存器，就要付出：寄存器自身的 t_pcq + t_su（固定开销）、时钟功耗、面积。当“切出来的组合逻辑”短到与寄存器开销可比时，再切就没有收益了。

经验：每级组合逻辑的延时约为寄存器开销的 5~10 倍 时比较划算。这也是为什么主频停在几 GHz 后，工艺进步更多用于“多核”而不是“更深流水”。

6 时钟偏斜、抖动与时间借用

6.1 偏斜与抖动

理想情况下时钟同时到达所有触发器。实际上：

• 时钟偏斜（skew）：同一个时钟沿到达不同触发器的时间差（由时钟树布线造成，是固定的系统性偏差）；

• 时钟抖动（jitter）：时钟周期的随机波动（由 PLL、电源噪声造成，是随机的）。

两者都会吃掉时序裕量。PPT 把它们合成一个“不确定量”T_unc：

Tunc = TJ1 + TJ2 + Tskew(10-8)
Tc-q + TPmax < T − TSU − Tunc(10-9)

这个式子就是考虑偏斜与抖动后的建立时间约束，也是 STA 工具里真正在算的式子。

保持时间一侧：

Tc-q + TPmin > TH + Tunc(10-10)

6.2 有用偏斜与时间借用

有用偏斜（useful skew）：故意让捕获时钟晚到一点，相当于“偷”了一点时间给这条路径——能救建立时间，但会恶化保持时间。这是后端工程师常用的“最后一招”。

时间借用（time borrowing）：如果两个锁存器（不是触发器）用互补时钟，前一级可以“借用”下一级的一部分时间（因为锁存器是电平敏感的，数据只要在时钟关闭前到达即可）。这让流水线的时序划分更灵活，代价是时序分析复杂得多。

8 异步接口与亚稳态

8.1 跨时钟域为什么会出错

当数据从一个时钟域（clk_a）传到另一个（clk_b）时，数据的变化时刻与 clk_b 完全没有关系。于是可能出现：数据恰好在 clk_b 的建立/保持窗口内跳变。此时触发器“不知道自己该采 0 还是 1”。

PPT 第 68~70 页问了一个好问题：RTL 里会显示 x，但物理世界里没有 x——Data_b 到底是什么电平？ 答案是三种可能：

① 采到 VDD（1）；

② 采到 GND（0）；

③ 停在中间电平，既不是 0 也不是 1——这叫亚稳态（metastability）。

8.2 亚稳态：第三种状态

亚稳态的物理原因：触发器内部是两个首尾相接的反相器（正反馈环）。正常情况下它稳定在两个“谷底”（0 或 1），但如果被推到“山顶”（VDD/2）附近，它会在山顶附近停留一段时间，然后随机滑向某一侧。

v(t) = VMS + [v(0) − VMS]·et/τ(10-11)

其中 V_MS 是亚稳态电压（≈VDD/2），τ 是正反馈的时间常数。停留时间是指数分布的：绝大多数情况很快恢复，但偶尔会停很久——这就是为什么亚稳态无法“彻底消除”，只能把发生概率降到足够低。

8.3 同步器：把概率降到可接受

解决办法是加同步器（synchronizer）：用目标时钟连续打两拍（或三拍）。第一级可能进入亚稳态，但给它一整个时钟周期恢复；到第二级时已经稳定，不会再传播亚稳态。

MTBF ∝ et_{r/τ} / (fclk·fdata)(10-12)

MTBF（平均无故障时间）随“恢复时间 t_r”指数增长。所以：时钟越慢、同步器级数越多，MTBF 越长。工程上一般要求 MTBF 远大于设备寿命（例如几千年）。

9 时钟分配网络：把时钟送到每个角落

10 PLL 与 DLL：时钟的“发动机”

10.1 为什么需要 PLL

芯片内部需要高频时钟，但外部晶振通常只有几十 MHz。另外时钟经过长距离传输后会有延迟和抖动。锁相环（PLL，Phase-Locked Loop）解决这两个问题：倍频、去偏斜、过滤抖动。

fsystem = N × fcrystal, fcrystal < 200 MHz(10-13)

10.3 DLL：把“振荡器”换成“延时线”

延迟锁相环（DLL）用一条压控延时线（VCDL）代替 VCO：参考时钟经过延时线，与自身比较相位，调延时直到两者对齐（延时 = 一个周期）。

9.2 七条核心结论

① 同步 = 用时钟对齐；异步 = 用握手等待。现代芯片以同步为主。

② t_pd 决定建立时间，t_cd 决定保持时间；一个看最慢、一个看最快。

③ 关键路径 = t_pd 最大的路径，它决定最高频率；关键路径不一定是最长逻辑，而是延迟最大的那条。

④ 保持时间违例与频率无关，只能加延时，且常在“太快”的角出现。

⑤ 流水线用延迟换吞吐；深度受寄存器开销限制。

⑥ 偏斜和抖动直接吃裕量；有用偏斜能救急，但会伤保持时间。

⑦ 跨时钟域必须加同步器；亚稳态只能把概率降到可接受，不能消除。

12 自测题（含详解）

1. 一条路径：t_pcq = 80 ps，t_pd = 450 ps，t_su = 60 ps，t_unc = 40 ps。求最高时钟频率。

2. 同一条路径，t_ccq = 50 ps，t_cd = 30 ps，t_hold = 70 ps。是否满足保持时间？若不满足怎么修？

3. 为什么关键路径要看 t_pd 而不是 t_cd？

4. 把一条 600 ps 的组合逻辑切成 3 级流水，每级寄存器开销 100 ps。最高频率从多少变到多少？

5. 跨时钟域传 8 位数据，为什么不能简单地在每一位上加同步器？应该怎么做？

6. 亚稳态为什么无法彻底消除？同步器是怎么起作用的？

参考答案

1. Tc > 80 + 450 + 60 + 40 = 630 ps → f < 1/630ps ≈ 1.59 GHz。

2. t_ccq + t_cd = 50 + 30 = 80 ps > t_hold = 70 ps，勉强满足（余量 10 ps）。若工艺角变化导致 t_cd 变小就会违例，修法：在该路径插入延时单元（buffer）增加 t_cd。

3. 因为建立时间关心的是“数据最晚什么时候到”，所以用最慢路径 t_pd；而 t_cd 是最早到达时间，用于检查“会不会来得太早”（保持时间）。

4. 原：Tc = 600 + 100 = 700 ps → 1.43 GHz；切 3 级后每级 200 ps，Tc = 200 + 100 = 300 ps → 3.33 GHz。但单次运算要 3 个周期（延迟变大）。

5. 因为每一位的亚稳态恢复时间不同，8 位可能在不同周期被采到，组合出一个“从未存在过”的值。应该用握手或异步 FIFO（或用格雷码，如果数据是计数值）。

6. 亚稳态是正反馈系统的“山顶”平衡点，理论上可以无限接近山顶，所以停留时间没有上界（只是概率指数下降）。同步器给它一整个周期的恢复时间，使“到下一级时仍未恢复”的概率低到可接受。
